# Statement on the use of AI

We find generative AI to be a useful tool in software development _when used correctly_. We employ it within this context, and we ask our contributors to do the same.

## Our use of AI

We are using AI-powered agentic code assistants such as Claude Code, OpenAI Codex, Qwen Code, and JetBrains Junie to develop this software. Human developers do the engineering, have the final decision on the feature set and implementation path, and review – and frequently edit – the generated code.

At the end of the day, the person signing off the commit is responsible for the committed code. The tool used to create that code is irrelevant.

## Use of AI by contributors

We only expect our contributors to use generative AI in the same manner we do.

**Mark your submissions as using AI** if you used generative AI for anything other than translation or proofreading. AI tends to use terse language which in most cases would read as drivel. We can decode that if we know that's what we're looking at.

**No laundry list of unverified claims**. We run AI-assisted security audits using various frontier models quite regularly. Don't send us the same, long report; your issue will be closed without a reply.

**Only run it against the working copy, having installed the dependencies**. Do NOT run a code assistant against the distributed binary, or the source code ZIP file generated by GitHub. It will lack important context, leading to invalid results.

**Make sure it is reproducible**. Generative AI often hallucinates impossible issues. Ask it to create a Proof-of-Concept (POC). If it fails or produces something working, it was never a real issue.

**Check if it's a valid issue**. A reproducible issue doesn't mean a valid issue. Issues which only happen under deliberate misconfiguration, or which devolve to "I can hack myself" / "I can do exactly what my granted permissions allow me" are reproducible, but invalid. Generative AI does not understand who, when, where, or how will be using this software. It's _your responsibility_ to take that into account.

**Answer follow-up questions**. We will very likely ask for follow-up questions. If you are not willing to do that, please don't report an issue. Telling us something to the tune of "dunno, my chatbot told me to submit this" is the fastest way to get banned from this repository as a time-waster. Which brings us to the last and most important point.

**You have full responsibility for your submission**. When you submit a bug or security issue report, you take full responsibility for it. If it's wrong, nonsensical, or an outright bad idea (of which generative AI has plenty), it reflects on _you personally_, not the tools you used. If you're unsure about what you are submitting, spend more time on it to properly understand it first. This is what you're asking me to do; it's only fair you do it first for your own submission.
